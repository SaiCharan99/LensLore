# LensLore Infrastructure

Terraform 1.9+ on AWS. Provisions S3, RDS PostgreSQL, two Lambdas, CloudFront, IAM roles, and Secrets Manager entries.

For the resource-by-resource design rationale, see [AGENTS.md](AGENTS.md).

## Prerequisites

- Terraform 1.9+ (`brew install terraform`)
- AWS CLI 2 configured with credentials (`aws configure` or `AWS_PROFILE=…`)
- Node.js 20+ (the Lambda module zips bundles produced by `../lambdas/npm run build`)

## First-time setup (per AWS account)

```bash
# 1. Build the Lambda bundles — the lambda module zips them from ../lambdas/dist/
cd ../lambdas && npm install && npm run build && cd -

# 2. Bootstrap the S3 bucket Terraform uses for remote state. One-time.
./bootstrap.sh

# 3. Initialise providers + connect to the state backend
terraform init

# 4. Create the dev workspace and switch to it
terraform workspace new dev
```

## Per-deploy flow

```bash
# Optional: pass the Anthropic key as a TF_VAR so it lands in Secrets Manager.
# Skip this if you'd rather populate the secret manually after apply.
export TF_VAR_anthropic_api_key="sk-ant-..."

terraform plan  -var-file=env/dev.tfvars
terraform apply -var-file=env/dev.tfvars

terraform output            # S3 bucket, RDS endpoint, Lambda ARNs, CloudFront domain
```

For prod: `terraform workspace select prod` (create with `terraform workspace new prod` the first time), then point at `env/prod.tfvars`.

## Layout

```
infrastructure/
├── versions.tf              Terraform / provider versions, S3 backend
├── providers.tf             Default aws (eu-west-1) + aliased aws.us_east_1 for ACM
├── variables.tf             Input variable declarations
├── locals.tf                name_prefix, common_tags
├── main.tf                  Module composition + Symfony IAM role/SG
├── outputs.tf               Wiring values for the Symfony backend's .env
├── bootstrap.sh             One-time state-bucket creator
├── env/
│   ├── dev.tfvars           t3.micro, single-AZ, PriceClass_100
│   └── prod.tfvars          t3.medium, multi-AZ, PriceClass_All
└── modules/
    ├── secrets/             Secrets Manager: Anthropic key + auto-generated DB password
    ├── s3/                  Photos bucket (block public, encrypted, versioned, lifecycle)
    ├── rds/                 PostgreSQL 15 in default VPC, locked-down SG
    ├── lambda/              Function + IAM role + CloudWatch logs (zips from ../lambdas/dist/)
    └── cloudfront/          Distribution with OAC + optional custom domain + ACM cert
```

## Notes worth knowing

- **State bucket is global.** The `lenslore-tf-state` bucket name in [`versions.tf`](versions.tf) must be globally unique. If it's taken, change the bucket name there (and in [`bootstrap.sh`](bootstrap.sh)) before running.
- **Default VPC.** RDS sits in the account's default VPC for portfolio-grade simplicity. Production would use a dedicated VPC with private subnets — the security groups and `app_security_group_id` plumbing would carry over.
- **CloudFront circular dep.** The S3 bucket policy needs the CloudFront ARN. The cloudfront module creates the distribution first, then attaches the bucket policy, breaking the cycle.
- **OAC, not OAI.** The S3 origin uses Origin Access Control (the modern path), not the legacy Origin Access Identity.
- **ACM in us-east-1.** CloudFront only accepts ACM certs from `us-east-1`. Set `cdn_domain_name` to enable; the cert is provisioned via the aliased `aws.us_east_1` provider. Validation is DNS — add the CNAMEs returned in `acm_certificate_validation_records` to your DNS.
- **Anthropic key handling.** Pass via `TF_VAR_anthropic_api_key` env var so it never touches a `.tfvars` file. If left empty, Terraform creates the secret resource but doesn't populate it — set it via `aws secretsmanager put-secret-value` afterwards.
- **DB password.** Auto-generated by `random_password`, stored in Secrets Manager, fed to RDS. To rotate, taint `module.secrets.random_password.db` and re-apply (RDS will pick up the new password; restart the Symfony app).

## Validate without applying

```bash
terraform fmt -recursive -check
terraform validate
```

Both pass on a clean checkout (no AWS credentials needed for these).
